# Modernizacja zależności i natywnego toolchainu FAZY 2

Zmiana centralizuje graph zależności, zachowuje lokalny fork Media3 1.8.0, dodaje kontrolowany source-mode FFmpeg, odtwarza IAMF dla stron 16 KB i naprawia JNI Dovi po rebrandingu. C1, C2 i C3 potwierdzają kompilację obu trybów playera oraz 1325 testów debug bez failures/errors. Najważniejszy blocker pozostaje poza tym dowodem: oba nowe `CMakeLists.txt` istnieją tylko lokalnie, ponieważ globalne `*.txt` je ignoruje, więc clean checkout nie odtworzy C1 ani włączonego Dovi. Pozostałe luki dotyczą fail-closed, trwałego egzekwowania integralności i runtime native; zatwierdzone M2/M3 i Cloudstream lifecycle nie zostały ponownie otwarte.

Watch for: **[P1, confirmed]** dwa wymagane pliki CMake są ignorowane i nie należą do Git; **[P2, confirmed]** jawne żądanie realnego linku Dovi może zakończyć się poprawnym buildem stubu; **[P2, confirmed]** native lock/audyt nie jest podłączony do standardowego `check` ani CI; **[P2, confirmed]** zdalny graph ma piny wersji, ale nie ma Gradle dependency verification/lockfiles; **[P2, confirmed]** zmieniony produkcyjny IAMF i pozostałe ścieżki JNI nie mają jeszcze device-runtime gate.

## High-level view

Katalog wersji skupia toolchain wokół jawnych pinów, a sześć lokalnych AAR Media3 nadal zastępuje odpowiadające moduły Maven bez zmiany linii 1.8.0. **[P2, confirmed]** Graf nie jest jednak deterministyczny na poziomie bajtów pobieranych artefaktów, bo repozytoria — w tym JitPack — nie są objęte metadanymi weryfikacji ani lockami transitives.

FFmpeg ma jeden selektor dla source i prebuilt; source-mode sprawdza commit, checkout, NDK/API, codec set i cztery ABI, a prebuilt pozostaje produkcyjnym defaultem. **[P1, confirmed]** Source-mode i Dovi nie są przenośne do patcha, ponieważ oba wymagane `CMakeLists.txt` są ignorowane przez Git.

IAMF ma reprodukowalną recepturę i kontrolowaną podmianę ośmiu ELF, a standalone audit sprawdza lokalne hashe, ABI, JNI i 16 KB alignment. **[P2, confirmed]** Dovi może zdegradować jawnie żądany real-link do stubu; **[P2, confirmed]** audyt pozostaje ręczną bramką; **[P2, confirmed]** statyczne wyniki nie dowodzą Android load/decode/playback dla nowego IAMF, Dovi ani kandydata FFmpeg.

## Clean checkout traci oba natywne entrypointy

**[P1, confirmed]** `.gitignore:65` ignoruje każde `*.txt`, więc `app/src/main/cpp/CMakeLists.txt` i `ffmpeg-decoder-downmix/src/main/jni/CMakeLists.txt` są wskazywane przez `git check-ignore`, ale oba kończą `git ls-files --error-unmatch` błędem. `app/build.gradle.kts:237-240` ustawia pierwszy plik jako entrypoint Dovi, a `ffmpeg-decoder-downmix/build.gradle.kts:165-170` ustawia drugi jako entrypoint source-mode.

C1 przeszło wyłącznie dlatego, że pliki były obecne w tym working tree. Po utworzeniu patcha lub świeżego checkoutu Dovi z `DOVI_NATIVE_ENABLED=true` nie skonfiguruje się, a `USE_LOCAL_FFMPEG_DECODER=true` nie zbuduje kandydata. Należy dodać precyzyjne wyjątki dla obu ścieżek, jawnie dodać pliki do Git, potwierdzić je przez `git ls-files` i odtworzyć C1 z czystego worktree.

## Piny wersji nie ustalają tożsamości artefaktów z repozytoriów

**[P2, confirmed]** `gradle/libs.versions.toml:2-60` przypina wersje, w tym strict constraints, a `settings.gradle.kts:22-27` centralizuje Google, Maven Central i JitPack. W repozytorium nie ma `gradle/verification-metadata.xml`, lockfile ani konfiguracji `dependencyLocking`; C3 dowodzi graphu rozwiązanego w danym przebiegu, nie SHA-256 artefaktów pobranych w przyszłym clean buildzie.

Ryzyko jest największe dla koordynatów JitPack opartych na tagach (`cloudstream = "v4.7.0"` i `com.github.*` w `gradle/libs.versions.toml:46-48,164-166`), ale obejmuje też transitives. Należy dodać zreviewowane Gradle dependency verification w trybie strict, a dla pełnego zamrożenia graphu również locki rozwiązywanych konfiguracji.

## Żądany real-link Dovi kończy się niewiernym stubem

**[P2, confirmed]** `app/build.gradle.kts:89-94,189-194` tłumaczy `DOVI_ENABLE_REAL_LINK=true` na `-DDOVI_ENABLE_LIBDOVI=ON`, lecz `app/src/main/cpp/CMakeLists.txt:72-78` emituje tylko `message(WARNING)`, gdy dla ABI nie znajdzie archiwum. Następnie `app/src/main/cpp/CMakeLists.txt:110-113` kompiluje `DOVI_REAL_LINKED=0`; JNI zwraca `nativeIsConversionPathReady() == false` (`dovi_bridge.cpp:101-119`), a Kotlin odrzuca konwersję (`DoviBridge.kt:92-120`).

Runtime degraduje się bez korupcji próbek, ale release deklarujący real link może wyjść bez żądanej funkcji. Świadome `OFF` powinno nadal budować stub; brak archiwum przy `ON` powinien kończyć konfigurację przez `message(FATAL_ERROR)`.

## Native lock jest dowodem jednorazowym, nie stałą bramką

**[P2, confirmed]** `tools/native/audit_native_artifacts.py:937-1088` sprawdza kontrakty Dovi/FFmpeg i przypięty inventory, a przy błędach zwraca kod 1 (`:1359-1369,1593-1597`). Jedyne wywołania znajdują się jednak w ręcznym runbooku `.kiro/research/dependency-modernization/PHASE2_EXTERNAL_GATES.md:159-160,198-255,352-355`; przeszukanie Gradle i `.github/workflows` nie znalazło konsumenta.

Zmiana AAR/SO, niespójność locka, utrata JNI lub regres 16 KB może przejść zwykłe `check`/assemble/CI, jeśli runbook zostanie pominięty. Lekki audyt bazowego inventory powinien być taskiem zależnym od `check` lub release preflight i krokiem CI; długie rebuildy Dovi/FFmpeg mogą pozostać zewnętrzne.

## Statyczne ABI nie dowodzi działania zmienionego dekodera

**[P2, confirmed]** Produkcyjny `app/libs/lib-decoder-iamf-release.aar` został zastąpiony, ale jego dokumentacja wprost pozostawia realne dekodowanie na Androidzie jako osobny gate (`tools/native/iamf/README.md:107-110`). Ogólny raport oznacza finalny APK jako niesprawdzony i wyklucza z dowodu JNI/decode/playback (`PHASE2_NATIVE_AUDIT.md:108-114`).

Przed release potrzebny jest test załadowania JNI i znanej próbki IAMF na reprezentatywnym urządzeniu 64-bit, rozszerzony na deklarowaną macierz ABI. Dovi wymaga analogicznego start/self-test przy realnym linku. Source FFmpeg pozostaje kandydatem (`ffmpeg-decoder-downmix/README.md:84-94`), więc jego device matrix jest warunkiem dopiero przed zastąpieniem produkcyjnego prebuilt.

## Granica parity FFmpeg

Source FFmpeg celowo nie jest deklarowany jako byte-for-byte parity: historyczny prebuilt ma nieustalony commit i obejmuje `mlp`, kandydat opiera się na przypiętym n7.1.5 i dodaje mapowane H.264/HEVC. Jeden `foxtvUseLocalFfmpegDecoder` zapobiega jednoczesnemu dołączeniu obu artefaktów (`settings.gradle.kts:41-53`, `app/build.gradle.kts:642-647`), a dokumentacja zabrania podmiany bez API/ABI i device playback gates. C1/C2 są zatem dowodem build/test kandydata, nie runtime parity.

`/tmp/fox_phase2_c1_retry_20260913_124118/SUMMARY.txt` potwierdza walidację wejść, release AAR, audyt kandydata i kompilację source-mode. `/tmp/fox_phase2_c2_after_brand_20260913_182622/SUMMARY.txt` potwierdza FanFilm 25, Aniyomi 114, Cloudstream 59, dependency consumers 79 oraz po 369 testów playera w default/source mode, bez failures/errors. `/tmp/fox_phase2_c3_20260913_183241/SUMMARY.txt` raportuje `FULL_DEBUG|tests=1325|failures=0|errors=0|skipped=1` i `C3_STATUS=PASS`.

Clean, lint, release/R8, finalny APK i device runtime nie zostały wykonane ani oznaczone jako PASS.
