# Scoped Cloudstream TLS and external-plugin lifecycle hardening

The change replaces process-wide Conscrypt installation and trust-all TLS with a client-scoped trust manager, then validates metadata and staged `.cs3` artifacts before activation. It also adds partial-refresh preservation, disabled-plugin filtering, and owner attribution for Cloudstream’s global providers and extractors. The resolved graph matches Cloudstream v4.7.0’s Rhino 1.8.1 and NiceHttp 0.4.17 requirements, with NiceHttp and the application both resolving OkHttp 5.3.2; all 18 targeted unit tests pass. The scoped diff still has six P1 lifecycle/security blockers; no P0 path was identified.

Watch for: **confirmed, P1 blocker** — cleartext or TLS-downgraded repository metadata can authorize arbitrary executable code; **confirmed, P1 blocker** — an active plugin rejected for malformed update metadata is deleted as stale; **confirmed, P1 blocker** — refresh activation is neither serialized nor transactionally rolled back; **confirmed, P1 blocker** — provider cleanup observes `allProviders` but leaves `APIHolder.apis`/`apiMap` registrations behind; **confirmed, P1 blocker** — distinct extractors sharing a `mainUrl` escape ownership; **confirmed, P1 blocker** — disabling a plugin does not unload its globally registered code; **confirmed, P2 non-blocker** — relative references after redirects use the pre-redirect URL.

**Verdict**: NEEDS_CHANGES

## High-level view

The scoped TLS factory keeps Conscrypt out of the global JCA provider list and retains platform trust and hostname verification. The pins are aligned, but the executable repository pipeline accepts `http://` and scheme-changing redirects, bypassing that secure boundary (**confirmed, P1 blocker**).

`repo.json` and `plugins.json` references now use RFC-style resolution, with status, API version, size, SHA-256, extension suffix, and repository URL gated before download. Rejections do not affect completeness, so malformed active updates become authoritative removals (**confirmed, P1 blocker**); redirects also discard the effective response URL needed as the next base (**confirmed, P2 non-blocker**).

Per-file staging preserves the active target for size, hash, ZIP/DEX, and class-validation failures. Files are nevertheless activated before aggregate state commits, without a repository/target mutation lock, so cancellation and concurrent refresh can separate metadata from the active artifact (**confirmed, P1 blocker**).

Provider cleanup targets only one Cloudstream provider collection, extractor ownership collapses different instances by URL, and disable toggles do not evict loaded globals. Replaced or disabled external code can therefore remain process-wide (**confirmed, P1 blockers**).

2. **Rejected update becomes deletion** — **P1 blocker, confirmed.** An active existing plugin rejected for malformed update metadata is omitted from `desiredIds` and deleted as stale; preserve it unless metadata authoritatively marks it inactive or absent.

4. **Provider mappings survive cleanup** — **P1 blocker, confirmed.** Ownership watches `allProviders`, but registration also updates `APIHolder.apis`/`apiMap`; track actual registered identities and invoke Cloudstream’s mapping-removal lifecycle.
5. **Duplicate extractor identity leak** — **P1 blocker, confirmed.** Distinct extractor objects sharing a `mainUrl` collapse onto one ownership record, leaving the second object global after all owners are removed; separate identity ownership from URL deduplication.
6. **Disable leaves code globally active** — **P1 blocker, confirmed.** Toggle paths persist flags without evicting loaded providers/extractors, so disabled code remains reachable through shared Cloudstream registries; unregister external ownership after the disable commit.
7. **Redirect-relative URL base is stale** — **P2 non-blocker, confirmed.** Nested relative references resolve against pre-redirect URLs; carry `response.request.url` with each body and use it as the next base.

<summary>Details</summary>

### Cleartext metadata remains an executable-code trust path — P1 blocker, confirmed

`ExternalRepositoryContract.resolveHttpUrl` accepts HTTP and HTTPS because it only requires an OkHttp `HttpUrl` (`ExternalRepositoryContract.kt:24-29`). Repository intake preserves explicit `http://` (`PluginManager.kt:104-114`), and metadata/artifact clients follow redirects without rejecting a final cleartext URL (`ExternalRepoParser.kt:134-145`, `ExternalExtensionLoader.kt:174-181,228-245`). The application cleartext policy permits these requests.

When `plugins.json` arrives over HTTP, an on-path attacker can replace both its SHA-256 metadata and the `.cs3`, after which the validated DEX executes in-process. HTTPS input can also redirect to HTTP because the clients never inspect the effective scheme. Require HTTPS for manifests, plugin lists, artifacts, and effective redirect destinations, with any loopback/development exception explicit and non-production.

### Rejected active updates are converted into stale deletions — P1 blocker, confirmed

The parser records rejections but defines completeness solely as successful list fetch/parse (`ExternalRepoParser.kt:74-80`); direct `plugins.json` results default to complete with non-zero `rejectedPluginCount` (`ExternalRepoParser.kt:92-101`). Refresh passes only `isComplete` into reconciliation (`PluginManager.kt:623-634`), which builds `desiredIds` from accepted entries and deletes all other prior artifacts when accepted downloads succeeded (`PluginManager.kt:1196-1211`).

An existing status-`1` plugin with a missing hash, invalid size, unsupported API version, or malformed field disappears from `plugins`; no download fails, so its working artifact is deleted as stale. Carry observed identities and rejection reasons through parsing: explicit inactive status or true absence can remove an artifact, while active-but-unverifiable entries must block stale cleanup.

### Refresh activation is not a serialized repository transaction — P1 blocker, confirmed

`refreshRepository` is outside the reconciliation mutex (`PluginManager.kt:592-641`), while `downloadDexExtensions` activates files before saving the aggregate scraper list (`PluginManager.kt:1127-1211`). `activateWithRollback` performs `target -> backup` then `staged -> target` (`ExternalExtensionInstaller.kt:207-240`), but the loader monitor covers class validation, not activation (`ExternalExtensionLoader.kt:239-267`).

Two same-plugin refreshes can interleave: one moves the old target aside; the other sees no target and activates; the first then hits a destination collision, deletes the second artifact, and restores the old version even though the second refresh can persist new metadata. Cancellation or datastore failure after a child activation similarly leaves replacements and evicted caches without aggregate rollback. Serialize mutations per repository/target and retain transaction backups until scraper/repository metadata commits, restoring all activated artifacts on cancellation or persistence failure.

### Provider cleanup watches the wrong Cloudstream state — P1 blocker, confirmed

The compatibility `Plugin.registerMainAPI` calls `APIHolder.addPluginMapping` (`com/lagradost/cloudstream3/plugins/Plugin.kt:46-53`). In the resolved Cloudstream v4.7.0 AAR, that updates `APIHolder.apis` and rebuilds `apiMap`; its lifecycle counterpart is `removePluginMapping`, while `BasePlugin` additionally appends to `allProviders`. Owner capture and cleanup only mutate `APIHolder.allProviders` (`ExternalExtensionLoader.kt:730-772,780-795`) and never call `removePluginMapping`.

Compatibility-base providers are not captured at all; BasePlugin providers are removed only from `allProviders` and remain in `apis`/`apiMap`. Capture the actual provider identities registered by each plugin and remove them through Cloudstream’s mapping lifecycle as well as `allProviders`, preserving shared and built-in registrations.

### Same-URL extractor instances can never be reclaimed — P1 blocker, confirmed

Plugin registration inserts an extractor into the global list before owner reconciliation (`com/lagradost/cloudstream3/plugins/Plugin.kt:55-60`). `registerExtractor` keys ownership by normalized `mainUrl`; an existing key adds the owner to the first extractor and returns (`ExternalExtractorRegistry.kt:31-46`). `claimNewRegistrations` then recognizes only that exact first object (`ExternalExtractorRegistry.kt:55-64`).

If two plugins contribute different instances for one host, the second instance stays in `extractorApis` without an ownership record. Removing both owners eventually removes the first instance but leaves the second stale. Track identities separately from URL canonicalization, or immediately remove the directly inserted duplicate while attributing its owner to the canonical instance; test the real pre-insertion sequence with two distinct objects.

### Enabled filtering does not deactivate loaded globals — P1 blocker, confirmed

The new flow and execution guard require both `enabled` and `manifestEnabled` (`PluginManager.kt:293-298,844-850`), but `toggleScraper` and `toggleAllScrapersForRepo` only persist flags (`PluginManager.kt:654-680`) and never invoke `evictCache` (`ExternalExtensionLoader.kt:721-797`).

Loaded provider mappings and extractors therefore survive disable. Other enabled providers can still reach those extractors through Cloudstream’s shared `loadLinks` machinery until refresh, deletion, or process restart. After persisting a disable, evict that external owner; apply equivalent cleanup to repository/global disable transitions while retaining registrations with another enabled owner.

### Redirects lose the next relative-resolution base — P2 non-blocker, confirmed

`fetchBody` follows redirects but returns only the body (`ExternalRepoParser.kt:134-145`). `repo.json` resolves lists against the original input (`ExternalRepoParser.kt:60-68`), and `fetchPluginList` passes its pre-redirect URL to artifact preparation (`ExternalRepoParser.kt:110-128`). Relative references after a path/host redirect therefore fetch the wrong resource or fail. Return `response.request.url` with each body and use it as both nesting levels’ base; also enforce HTTPS on that effective URL.
