## Git visibility i handoff do przyszłego patcha

Poprzedni P1 wynikał z asymetrii: Gradle wskazywał oba `CMakeLists.txt` jako wejścia buildów, lecz globalne `*.txt` usuwało je z normalnego inventory untracked files. Reguły `!app/src/main/cpp/CMakeLists.txt` i `!ffmpeg-decoder-downmix/src/main/jni/CMakeLists.txt` znajdują się po regule ogólnej i nie rozszerzają wyjątku na inne pliki tekstowe.

**[resolved, confirmed]** `git check-ignore -q` kończy się kodem 1 dla każdej ścieżki, `git ls-files --others --exclude-standard` zwraca obie ścieżki, a `git status --short` pokazuje oba wpisy jako `??`. `git add --dry-run -- <obie ścieżki>` wybiera oba pliki i kończy się kodem 0 bez zmiany indeksu. Standardowe zebranie przyszłej zmiany obejmie więc oba entrypointy; ich aktualny status untracked nie jest już ukryty przez ignore.

`git diff --check` zakończył się kodem 0. Zgodnie z ograniczonym zakresem nie uruchamiano Gradle, release, R8, APK ani device gates i nie wymagano stage/commita.
